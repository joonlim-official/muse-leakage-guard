## Findings

### HIGH

**H1 — No-JS progressive enhancement: all card evidence unreachable with JavaScript disabled (WCAG 4.1 / robustness; content loss)**
- Evidence: `/tmp/a11y-report.html` rendered with `--disable-javascript` (screenshot `/tmp/a11y-shots/nojs-desktop.png`). Card details are `<div class="detail" … hidden>` toggled only by the inline `<script>`; with JS disabled the six `<button class="card-head">` elements are dead controls. The per-suite "tested" blurbs, full evidence lists, tri-state evidence groups, confusion matrix, per-case table, CI lower-bound lines, and operational notes are all inside those hidden divs. The Findings "evidence →" anchors also point at cards that cannot be opened.
- What still works without JS: hero, badge, mode bars, legend, summary totals, Raw transcripts (`<details>`/`<summary>` are native).
- Recommendation: replace the button+`hidden` disclosure with native `<details>`/`<summary>` (progressively enhanced with the existing styling and auto-expand behavior), or emit a `<noscript>` block that unhides all `.detail` divs. Keep `aria-expanded` wiring for the JS path.
- Residual if not fixed: keyboard/AT users are unaffected (JS path is keyboard-operable), but no-JS readers — and any environment that strips scripts, including some archival/reader pipelines — lose the report's entire evidence section, which is the substantive content of a validation report.

### MEDIUM

**M1 — Transcript `<pre>` scroll region is not keyboard-scrollable (WCAG 2.1.1)**
- Evidence: `.transcript pre` CSS (`bin/leakage-report`, `max-height:320px;overflow:auto`) with no `tabindex`. The raw transcripts are the longest content on the page and routinely exceed 320px; a keyboard-only user cannot move focus into the `<pre>` to scroll it. Same latent pattern on `.tablewrap` (`overflow-x:auto`) — measured non-overflowing with the current corpus, but a longer case name or non-standard-verdict line could overflow at 390px and would then be unreachable by keyboard.
- Recommendation: add `tabindex="0"` with an `aria-label` (e.g. "Scrollable transcript: bin/leakage-audit") to the transcript `<pre>` elements, and to `.tablewrap` (or make the inner table keyboard-focusable). One-line CSS/HTML change, no behavior change for pointer users.
- Residual if not fixed: keyboard-only users cannot read transcript content beyond the first 320px; latent horizontal-scroll trap for the matrix/per-case tables on narrow viewports if content ever widens.

### LOW

**L1 — No skip link (WCAG 2.4.1)**
- Evidence: page structure is hero → 6 card buttons → totals → transcripts. A keyboard/SR user must tab through all six disclosures to reach the transcripts. 
- Recommendation: add a "Skip to transcripts"/"Skip to summary" skip link as the first focusable element (visually hidden until focused). Trivial, standard pattern.
- Residual if not fixed: minor tab-order friction; not a barrier.

**L2 — Confusion-matrix corner header wording ("expected \ actual")**
- Evidence: `<th scope="col">expected \ actual</th>` in the 3×3 matrix (`bin/leakage-report`, matrix_html). The row headers say "block-tier (want rc=1)" and column headers "got rc=1", which disambiguates for sighted users, but the backslash convention is jargon-y for screen-reader users hearing the corner cell out of context.
- Recommendation: give the corner `<th>` an `aria-label` such as "Rows are expected verdicts; columns are actual verdicts", or change the visible text to "expected ↓ / actual →". 
- Residual if not fixed: low — row/column headers already carry "want"/"got" wording, so meaning is recoverable.

**L3 — `.card.skip` has no explicit style rule; yellow legend entry has no card-border counterpart**
- Evidence: `render_card` in `bin/leakage-report` can emit `class="card skip"`, but the `<style>` block defines only `.card.ok`, `.card.red`, `.card.stub` — skip cards silently fall back to the default `--mut` gray border. Separately, the legend's 🟡 "protected through approval" never appears as a card border: a suite whose checks are all approval-gated skips renders gray-bordered with a 🟡 emoji in the callout text, so the legend's color key and the card chrome don't fully correspond.
- Recommendation: add an explicit `.card.skip{border-left-color:var(--mut)}` rule (documents intent), and either introduce a yellow border class for approval-gated-dominant suites or adjust the legend to note that 🟡 appears in callout text, not borders. Cosmetic; one-line CSS plus a legend wording tweak.
- Residual if not fixed: none functional — gray is already the de-facto skip color and text labels carry the meaning; purely a code-clarity/legend-fidelity nit.

## Non-issues explicitly checked

- Keyboard traps: none. Card buttons are native `<button>` (Enter/Space toggle via click handler, `aria-expanded`/`aria-controls`/`hidden` kept in sync); transcript disclosures are native `<details>`/`<summary>`; focus-visible outlines exist on `.card-head` and `summary`; links use the browser default focus indicator (no `outline:none` anywhere).
- Duplicate IDs: `callout-A…F`, `card-A…F`, `detail-A…F` all unique.
- Auto-expand of red cards runs on load and sets `aria-expanded="true"` consistently — no mismatch between visual and AT state.
- Mobile 390px: no horizontal page scroll, no clipped badges, matrix and per-case tables fit; cards stack full-width (screenshots `/tmp/a11y-shots/mobile.png`, `/tmp/a11y-shots/nojs-mobile.png`).
- Emoji are `aria-hidden="true"` with adjacent real text throughout; the decorative shield in the `h1` likewise.
- `lang="en"`, viewport meta, and `<title>` including the verdict word are present.
