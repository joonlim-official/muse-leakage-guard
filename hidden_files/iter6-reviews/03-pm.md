## Findings

### P0 — A red CI run is undiagnosable from the summary and artifacts

- **Severity:** P0
- **Evidence:** `.github/workflows/validate.yml`. If `bin/leakage-audit`
  exits 1, the `adversarial`, `report` steps have no `if: always()` and are
  skipped; only `Upload the validation report` and `Summarize the validation`
  run. The report was never generated, so the upload step's single-file path
  matches nothing and the step itself fails. The summary then contains only
  the header + disclaimer — its three `grep … || true` lines find nothing
  (audit.log exists but `grep -aE 'Total: …'` may match; the adversarial lines
  cannot). The sharpest form: the failure mode CI is *most* likely to catch —
  an adversarial mismatch with a passing audit — also skips the report step
  (adversarial step exits 1, report never runs), so the summary shows the
  audit line and zero adversarial evidence. A PR author gets a red job, a
  failed upload, and an empty summary.
- **Recommendation:** `if: always()` on the report-generation step (it already
  refuses to write a misleading report on unparseable input, so always() is
  safe); on failure also upload `audit.log` and `adversarial.log`; have the
  summary print a short failure tail (e.g. last 15 lines of the failing log)
  so the summary alone answers "what broke".
- **Residual if not fixed:** every future red run — exactly the moment a
  contributor needs guidance — presents a blank summary and no artifact, and
  contributors will learn that "red CI" carries no information, eroding trust
  in the harness.

### P0 — The summary's tier grep is dead: `block-tier recall` no longer exists

- **Severity:** High
- **Evidence:** `.github/workflows/validate.yml` summary step runs
  `grep -aE 'block-tier recall' "${{ runner.temp }}/adversarial.log" || true`.
  `bin/adversarial-run` prints `adversarial-run: block-tier pass 19/19 ·
  review-tier pass 9/9 · clean pass 8/8` (verified by running it: the
  `recall` grep returns zero lines, exit 0 via `|| true`, and the tier
  breakdown silently vanishes from every summary). The `|| true` makes the
  breakage invisible — the summary is green-and-complete-looking while
  omitting the per-tier figures. The other two greps match human text
  (`Total: … passed`, `… cases matched`) and are one output-format change
  away from the same silent loss.
- **Recommendation:** stop grepping human text. The audit already emits
  machine sentinels (`@@@ TOTAL`, `@@@ VERDICT`, `STUBKIND`) consumed by
  `bin/leakage-report`; have the summary parse those (or have
  `bin/leakage-report` write a small `summary.json` artifact and let CI echo
  its fields). At minimum, change the grep to `block-tier pass` so today's
  summaries show the tiers.
- **Residual if not fixed:** PR authors cannot rely on any line of the
  summary — a silent format drift is indistinguishable from "nothing to
  report", and the tier pass rates (block 19/19, review 9/9, clean 8/8) that
  a reviewer needs to judge a regression never appear.

### P1 — The verdict badge collapses tri-state into red

- **Severity:** Medium
- **Evidence:** `bin/leakage-report:200-204,620` — `badge_word` is tri-state
  (`CLEAN` / `ATTENTION` / `INCOMPLETE`; ATTENTION comes from the audit's
  `VERDICT: ATTENTION — $FAIL finding(s) need review.`,
  `bin/leakage-audit:226`, and auto-triggers when a CLEAN audit has
  adversarial mismatches). But the badge class is binary:
  `{"ok" if clean else "bad"}`. So ATTENTION and INCOMPLETE render red.
  The legend (`bin/leakage-report:499-512`) defines 🔴 as "can leak — a check
  failed, or something that should have been stopped was not". An ATTENTION
  report whose finding is, say, a failed static coverage check (no actual
  leak path) is visually declared "can leak", overstating the finding and
  training readers to distrust the badge.
- **Recommendation:** a third badge color for ATTENTION (amber, matching the
  legend's 🟡 "protected through approval"/attention semantics) and a neutral
  treatment for INCOMPLETE ("report could not be trusted" ≠ "can leak").
- **Residual if not fixed:** non-leak findings get screenshot as "can leak",
  and the tri-state semantics iter5 added exist in text but not in the
  highest-salience element.

### P1 — README's residual table is stale against the actual suite E

- **Severity:** Medium
- **Evidence:** README section "E. Known residuals — reported every run,
  never silent" lists 4 rows (browser-task sends, absolute-path bypass, voice
  calls, brief gating). The audit's actual suite E (verified in the generated
  `/tmp/iter6pm/report.html`) lists **9** residuals, including compositional/
  chunked exfiltration, out-of-band egress (curl/webhooks/unshimmed CLIs),
  the A7 static-cron-check caveat, attachment inspection (B4 open gap), and
  the bare-nine-digit SSN false-positive trade-off. A first-time reader who
  learns the residual story from the README sees a smaller set than the
  report shows. Separately, README's E1–E4 numbering collides with
  `references/attack-surface.md`'s E1–E3 ("Classification": over-gating,
  stub-confusion, SSN false-positive) — a reader cross-referencing "E2"
  lands on a different scenario depending on which file they are in.
- **Recommendation:** sync the README E table to the 9 residuals the audit
  actually re-reports every run (it can stay terse — one line each), and
  either renumber one of the two E-series or label the README rows "R1.."
  so cross-references are unambiguous.
- **Residual if not fixed:** the "never silent" promise holds in the report
  but the README quietly under-describes the residual surface, and "E2"
  means two things.

### P2 — The README tagline is the one unqualified protection claim

- **Severity:** Medium
- **Evidence:** `README.md:4` — "It doesn't protect anything itself — it
  **proves the protection works**, finds the holes, and suggests the fix."
  Everything below is carefully qualified, but this is the sentence GitHub
  shows as the repo snippet and the sentence a drive-by reader remembers.
  "Proves the protection works" with no object qualifier reads as a blanket
  protection claim for anyone who never scrolls to the CI section.
- **Recommendation:** qualify the object once, up front:
  "it *proves the protection holds against synthetic red-team probes*".
- **Residual if not fixed:** the misreading the stub banner exists to prevent
  survives at the top of the page that links the badge.
