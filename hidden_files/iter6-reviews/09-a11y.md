## Findings

### 1. Medium — Links have no explicit color: dark-mode contrast ≈ 1.9:1
**Evidence:** `bin/leakage-report` (embedded CSS, generated by the `page` f-string):
no `a{color}` rule anywhere; `.flink` sets only `font-size`/`font-weight`/`white-space`.
Affected links: findings "evidence →" anchors, the CI run link in the header `.meta`.
In dark mode (`prefers-color-scheme: dark`, `--card:#15181d`) Chrome keeps the default
link blue `#0000EE`, which computes to 1.89:1 on `#15181d` (visited purple `#551A8B`
is ~1.4:1) — both far below 4.5:1 (WCAG 1.4.3).
**Recommendation:** add explicit link colors for both schemes, e.g.
`a{color:#1d4ed8}` and `@media(prefers-color-scheme:dark){a{color:#93c5fd}}`,
and re-run the contrast check; keep `:visited` ≥ 4.5:1 as well. One-line CSS diff,
no scope expansion.
**Residual if not fixed:** dark-mode users (especially low-vision) cannot reliably
perceive findings links or the CI run link; the links are functionally invisible.

### 2. Medium — CI step summary carries no explicit text outcome
**Evidence:** `.github/workflows/validate.yml:146-157` ("Summarize the validation",
`if: always()`). It writes the header, the italic self-consistency disclaimer, then only
`grep` results (`Total: …`, `adversarial-run: …/…`, `block-tier recall …`), each with
`|| true` so a missing line silently produces nothing. No CLEAN/ATTENTION/FAILED word
appears anywhere. If the audit step fails (crash, parse drift, missing log), the summary
renders as header + disclaimer with no numbers and no outcome word — the failure is
communicated only by the step's red status indicator (color/icon) one level up in the
Checks UI, not in words on the summary surface itself.
**Recommendation:** append an explicit outcome line derived from the earlier steps'
exit codes / the audit VERDICT sentinel (e.g. `- Outcome: ATTENTION (audit exit 1,
adversarial exit 0)`), plus an explicit "audit figures unavailable — see step log"
note when a grep finds nothing. Text-only, no scope expansion.
**Residual if not fixed:** screen-reader users scanning the step summary get color/icon
status but no stated verdict; a silently-empty summary can be misread as "nothing to see".

### 3. Low–Medium — Transcript `<pre>` is a scrollable region with no keyboard access
**Evidence:** `bin/leakage-report` CSS: `.transcript pre{…max-height:320px;overflow:auto…}`;
no `tabindex`. Layout probe (headless Chrome, 360px): transcript `pre[0]`
`scrollHeight=9344` vs `clientHeight=318` — vertically scrollable, `tabindex=null`.
Keyboard-only users cannot move focus into it, so arrow keys / page keys never reach the
transcript content; mouse/touch users can scroll, keyboard users cannot.
(Same latent pattern on `.tablewrap{overflow-x:auto}`: in this CLEAN report the F-card
detail is `hidden` so no layout box exists to measure, but width estimates put the
per-case table ~70px over a 360px viewport, meaning horizontal scroll — equally
unfocusable — appears on red/stub reports at phone widths.)
**Recommendation:** add `tabindex="0"` + `role="region"` + a descriptive `aria-label`
(e.g. "Audit transcript, scrollable") to the scrollable `<pre>` and to `.tablewrap`.
Standard pattern, two-line diff.
**Residual if not fixed:** keyboard users cannot read audit/adversarial transcripts or
clipped table columns on narrow screens.

### 4. Low — Card toggles are JS-only; no-JS users get callouts but never the evidence
**Evidence:** `bin/leakage-report` `<script>`: `.card-head` click handler toggles the
`hidden` attribute; all `.detail` regions start `hidden` (verified: 6 `hidden` details
in emitted HTML, all `aria-expanded="false"`). With JS disabled or blocked, toggles are
inert and evidence is permanently unreachable; the report degrades to callouts only.
**Recommendation:** progressive enhancement — render details expanded by default and
collapse them via the same script on load (JS present ⇒ identical current behavior;
JS absent ⇒ full content). Alternatively use native `<details>`/`<summary>`.
**Residual if not fixed:** users with JS disabled see verdicts but no evidence, notes,
or per-case tables.

### 5. Low — Confusion-matrix corner header reads "expected \ actual"
**Evidence:** `bin/leakage-report` generates `<th scope="col">expected \ actual</th>`
for the matrix's top-left cell. Screen readers may announce the literal word
"backslash" ("expected backslash actual").
**Recommendation:** change to "expected vs. actual" (or "expected / actual").
**Residual if not fixed:** minor screen-reader annoyance on an otherwise well-labeled table.
