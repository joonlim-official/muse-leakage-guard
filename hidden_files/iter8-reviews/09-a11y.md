## Ranked findings (10)

### 1. HIGH — Card evidence is unreachable without JavaScript
All six suite cards render their evidence inside `<div class="detail" …
hidden>`. The `hidden` attribute is removed only by the inline `<script>`
(toggle on click; auto-expand for `.card.red`). With JS disabled, blocked,
or failed to load, there is no mechanism to reveal any evidence — including
the red "can leak" cards, whose auto-expansion is itself JS. The only
natively accessible disclosure on the page is the two transcript
`<details>` elements. The Findings "evidence →" anchor links also degrade:
they jump to a card whose evidence is still hidden. This is a WCAG 1.3.1 /
4.1.2 functional failure of the primary content, not a progressive
enhancement gap.

Implementable fix (pick one):
- Convert cards to native `<details>`/`<summary>`: keyboard, SR, and no-JS
  support come free; server-render the `open` attribute on red cards to keep
  the auto-expand behavior without JS.
- Or keep the button pattern and add `<noscript><style>.detail{display:block
  !important}</style></noscript>` plus server-rendered `aria-expanded="true"`.

### 2. HIGH — Scrollable regions are keyboard-inaccessible
Two scroll containers exist with no `tabindex`: `.tablewrap`
(`overflow-x:auto` around both F-card tables — the per-case table is wide on
mobile) and `.transcript pre` (`max-height:320px; overflow:auto`). Mouse
users can scroll them; keyboard-only users cannot reach the overflowed
content at all. WCAG 2.1.1.

Implementable fix: add `tabindex="0"` + `role="region"` + a descriptive
`aria-label` (e.g. `aria-label="Per-case want vs got, scrollable"`) to both
`.tablewrap` divs and the transcript `<pre>` elements. One-line change in
each of the three template sites in `bin/leakage-report`.

### 3. MEDIUM — Card titles nest `role="heading"` inside `<button>`
Each card title is `<span class="callout" role="heading" aria-level="2">`
inside `<button class="card-head">`. Headings nested in interactive content
are inconsistently exposed: some screen-reader/browser combinations omit
them from heading quick-navigation (H key / rotor), so the six suite titles
may vanish from the heading list while the real `<h1>` and `<h2>Raw
transcripts</h2>` remain — a confusing outline.

Implementable fix: restructure as `<h2 class="callout-wrap"><button
class="card-head" aria-expanded="false" aria-controls="detail-A">…</button></h2>`
(button is phrasing content, so this is valid HTML), move the margin/reset
styles to the `h2`, and drop the `role="heading"` span. Keeps the identical
visual design and the existing `aria-expanded`/`aria-controls` wiring.

### 4. MEDIUM — Touch targets below the 24px minimum (WCAG 2.5.8)
- `.flink` ("evidence →" in the Findings section): `font-size:.78rem`
  (~12.5px), no padding → target height ≈ 18.7px.
- `.transcript summary`: inherits `.8rem` (~12.8px) at `line-height:1.5` →
  ≈ 19.2px tall.
Both are under the 24×24 CSS px AA minimum. (`.card-head` is ≈ 50px+ and
passes.)

Implementable fix: `.flink{padding:4px 8px; margin:-4px -8px}` (keeps visual
size, grows the hit area) and `.transcript summary{padding:6px 0;
min-height:24px}`. Note 44px is the AAA/mobile ideal; 24px is the floor.

### 5. MEDIUM — No skip link
Keyboard and screen-reader users tab through the hero, mode bar(s), and
legend before reaching `<main>`. Those regions carry no focusable elements
today, but the pattern is fragile (the CI-run link in the footer proves
focusables can appear outside main) and a skip link is cheap insurance.

Implementable fix: add `<a class="skip" href="#main">Skip to main
content</a>` as the first body child, `<main class="wrap" id="main">`, and
the standard visually-hidden-until-focused CSS (reuse the existing `.vh`
pattern with `:focus` unclipping).

### 6. LOW — Confusion-matrix corner header renders a literal double backslash
The thead corner cell reads `expected \\ actual` in the HTML (the generator
source has `\\\\` inside the Python string, emitting two backslashes).
Screen readers announce "expected backslash backslash actual", and it looks
like an escaping bug to sighted readers.

Implementable fix: in `bin/leakage-report`, replace the corner label with a
plain-language one, e.g. `expected ↓ / actual →` with `aria-hidden` arrows,
or simply `expected vs actual`.

### 7. LOW — Repeated "evidence →" link text has no unique accessible name
Every Findings row ends with `<a class="flink" href="#card-X">evidence
→</a>`. Out of context (link lists, rotor), N identical "evidence →" links
are indistinguishable.

Implementable fix: add `aria-label`, e.g.
`aria-label="Evidence for: [B] egress gate: fake api key blocked (rc=1)"`,
reusing the finding title already in the template loop.

### 8. LOW — `.vh` visually-hidden class uses deprecated `clip:rect()`
`clip:rect(0 0 0 0)` is deprecated (though still universally supported).

Implementable fix: replace with `clip-path:inset(50%)` (keep the other
declarations). One-line CSS change.

### 9. LOW — The "Total" summary block has no heading
The `<div class="total">` (total passed/failed/skipped + audit verdict) is a
key landmark for SR users but exposes no heading, so it can't be jumped to
and its verdict line is only reachable by linear reading.

Implementable fix: add `<h2 class="vh">Overall result</h2>` (visually
hidden, keeps the current visual design) inside `.total`.

### 10. LOW — No explicit `:focus-visible` style for text links
`.card-head` and `summary` have styled `:focus-visible` outlines, but
`.flink` links rely on the UA default outline — thin and inconsistent,
especially in dark mode.

Implementable fix: extend the existing rule, e.g. `.flink:focus-visible{
outline:2px solid var(--ok); outline-offset:2px; border-radius:4px}`.

## Verified passes (no action needed)
- Contrast: all 18 measured pairs (badge, status marks, muted text, all four
  mode bars + stub bar, dark-mode variants, focus outline) pass WCAG AA
  (4.5:1); most exceed 6:1.
- Status is never color-only: ✓/✗/– marks pair with visually-hidden
  "Pass:/Fail:/Skipped:" text, emoji are `aria-hidden` with text callouts,
  the legend spells out each verdict in words, and the badge is a text word.
- Table semantics: both F-card tables have `<caption>` and `scope="col"` /
  `scope="row"` headers.
- Landmarks: `<header>`/`<main>`/`<footer>` present; `<html lang="en">`;
  descriptive `<title>` including the verdict word.
- Disclosure wiring: `aria-expanded` + `aria-controls` + `role="region"` +
  `aria-labelledby` on cards is correct when JS runs; red cards auto-expand
  with `aria-expanded="true"`.
- Reduced motion: the only animation (chevron rotate, 0.18s) is disabled
  under `prefers-reduced-motion`.
- Text-mode rendering: reading order is logical (hero → mode bar → legend →
  cards → total → transcripts); all content present in DOM order.
- No duplicate IDs; `aria-controls` targets all resolve.
