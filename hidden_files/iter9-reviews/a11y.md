## Findings confirmed by execution

### E1. [P1] No-JS: all evidence panels unreachable without JavaScript — on-disk only, fixed in HEAD

- **Where:** `leakage-validation-20260917-204438-9012.html`, the six
  `<div class="detail" id="detail-A…F" … hidden>` blocks; the only `<script>` in the file.
- **What:** Every card's evidence region starts with the `hidden` attribute, and the
  sole mechanism that removes it is the click handler in the page's `<script>`. With
  scripting disabled there is no `<noscript>` fallback and no other way to reveal the
  evidence.
- **Confirmed by execution:** stripped the single `<script>` block (simulating no-JS)
  and dumped the DOM — all 6/6 `.detail` regions still carry `hidden`; no `<noscript>`
  element exists. (The two `<details>` transcript disclosures still work natively, so
  the raw logs survive — but every summarized evidence list does not.)
- **Why it matters:** This report is a validation artifact. It gets archived, attached
  to CI runs, and read in locked-down contexts (email previews, readers, `file://`
  with scripting off). An audit report whose entire evidence body requires JS is not
  a trustworthy record — a reader literally cannot verify the verdict.
- **Remediation:** already in HEAD — `<noscript><style>.detail{display:block!important}</style></noscript>`
  plus red cards pre-expanded server-side. Remaining nits are S9/S10 below.
  Process fix: regenerate the checked-in report so the artifact ships the fix.

### E2. [P1] Keyboard: overflowing transcript `<pre>` is not focusable — on-disk only, fixed in HEAD

- **Where:** `leakage-validation-…9012.html`, `<section class="transcript">` → first `<pre>`.
- **What:** The audit transcript `<pre>` has `max-height:320px; overflow:auto` and its
  measured `scrollHeight` is **5078px** vs `clientHeight` 318px — it overflows — but it
  has no `tabindex`, so keyboard-only users cannot move focus into it and cannot scroll
  it. The content past the first ~320px is unreachable by keyboard.
- **Confirmed by execution:** DOM probe reported `pre[0] scrollH=5078 clientH=318
  overflows=true tabIndex=-1`.
- **Why it matters:** SC 2.1.1 (Keyboard) — all content must be operable through a
  keyboard interface. A scrollable region that can't receive focus fails this for
  keyboard and many switch-device users.
- **Remediation:** already in HEAD — `<pre tabindex="0" role="region"
  aria-label="bin/leakage-audit transcript, scrollable">` with a `:focus-visible`
  outline. Same treatment exists for `.tablewrap`. Regenerate the report to ship it.

### E3. [P2] Transcript `<summary>` is a 19px-tall target — on-disk only, fixed in HEAD

- **Where:** same file, `.transcript summary` ("Raw transcripts" disclosure).
- **What:** Measured **19px tall, full-width, 0px vertical padding**. Below the WCAG
  2.2 SC 2.5.8 24×24 CSS px minimum target size, and a poor touch target on phones —
  the primary way this report is read.
- **Confirmed by execution:** DOM probe `summary[0] h=19 w=419 pad=0px/0px`.
- **Why it matters:** Small disclosure targets are hard to hit for users with motor
  impairments and on touch devices; the transcript is the "verify it yourself" path.
- **Remediation:** already in HEAD — `.transcript summary{…padding:10px 0}` (≈39px).
  Regenerate the report to ship it.

## Findings from static analysis

### S1. [P2] Invalid HTML: `<h2>` nested inside `<button>` — on-disk only, fixed in HEAD

- **Where:** on-disk report, each card head:
  `<button class="card-head" …><span class="head-text"><h2 class="callout" …>…`.
- **What:** `<button>` permits only *phrasing content*; `<h2>` is not phrasing content.
  Browsers recover, but the DOM no longer matches the author's heading structure, and
  some assistive-technology/browser combinations compute the button's accessible name
  and heading navigation inconsistently from invalid nesting.
- **Why it matters:** SC 4.1.1 (Parsing) — content implemented with markup must use
  elements according to specification so AT can rely on it.
- **Remediation:** already in HEAD — `<h2 class="callout-wrap"><button class="card-head">…`
  (heading wraps the button, which is valid). Regenerate the report to ship it.

### S2. [P2] Per-case table: empty accessible column header + context-free ✓/✗ cells — on-disk only, fixed in HEAD

- **Where:** on-disk report, card F table:
  `<th scope="col"><span aria-hidden="true">match</span></th>` and cells like
  `<td class="cok">✓</td>`; case names in `<td>` instead of `<th scope="row">`.
- **What:** The fourth column's header is `aria-hidden`, so its accessible name is
  **empty** — screen readers announce the column with no header. The cells expose a
  bare "✓"/"✗" character with no text alternative, so a screen-reader user hears
  "check mark" under an unlabeled column. Row headers are also missing (`<td>` for
  case names), so row/column association is weaker than it should be.
- **Why it matters:** SC 1.3.1 (Info and Relationships) and 4.1.2 — the match/mismatch
  column is the *core verdict data* of the adversarial section; it must be
  programmatically determinable.
- **Remediation:** already in HEAD — visible `<th scope="col">match</th>`,
  `<th scope="row">` case names, `<caption>`, mark `aria-hidden` with an sr-only
  "matched"/"mismatched" text (`.vh` class). Regenerate the report to ship it.

### S3. [P2] No skip link — on-disk only, fixed in HEAD

- **Where:** on-disk report has no skip navigation; `<main>` exists but nothing links to it.
- **What:** Keyboard users must tab through the hero content and all six disclosure
  buttons before reaching anything else; there is no way to jump to the findings,
  the verdict total, or the transcripts.
- **Why it matters:** SC 2.4.1 (Bypass Blocks) — a mechanism to skip repeated blocks.
  The page is short, but the card list is the repeated block.
- **Remediation:** already in HEAD — `<a class="skip" href="#main">Skip to main
  content</a>` with off-screen-until-focus styling and a reduced-motion override.
  Regenerate the report to ship it.

### S4. [P3] Verdict total has no heading — on-disk only, fixed in HEAD

- **Where:** on-disk report `<div class="total"><b>Total: 58 passed …</b>…`.
- **What:** The single most important line of the report (overall verdict) is not a
  heading, so screen-reader users navigating by headings jump from the card `<h2>`s
  straight past the verdict to the transcript `<h3>`s.
- **Remediation:** already in HEAD — `<h2 class="vh">Overall result</h2>`. Ship it by
  regenerating.

### S5. [P2] The checked-in report is stale relative to the generator (process)

- **Where:** `hidden_files/reports/leakage-validation-20260917-204438-9012.html` vs
  `bin/leakage-report` at HEAD.
- **What:** Seven of this review's findings (E1, E2, E3, S1–S4) are already fixed in
  the HEAD template, but the newest checked-in report artifact predates those fixes.
  Anyone reviewing "the latest report" reads the less-accessible version.
- **Why it matters:** The report is the deliverable humans (and auditors) actually
  read. A fixed generator with a stale artifact means the fix never reaches a reader.
- **Remediation:** regenerate the report from HEAD after template changes
  (`bin/leakage-report --out …`), or stop checking generated reports into the repo and
  treat CI artifacts as the canonical copy. Either way, make staleness impossible or
  visible (e.g., embed the generator's git SHA in the report footer — cheap, and lets
  any reader verify which template produced the file).

### S6. [P2] CI has no accessibility regression gate for the generated HTML

- **Where:** `.github/workflows/validate.yml` ("Generate the HTML validation report"
  step) — asserts the stub banner, sentinels, exit codes, but nothing about the
  report's own accessibility.
- **What:** The a11y fixes in HEAD (skip link, noscript, table headers, tabindex on
  scroll regions, no heading-in-button) are all one template edit away from silently
  regressing. Nothing in CI would catch it.
- **Why it matters:** Accessibility of a *validation report* is load-bearing: if the
  report degrades, the human audit step degrades with it, and nobody is alerted.
- **Remediation:** add a CI step that runs after report generation and fails on:
  `<h2` inside `<button`, missing `href="#main"` skip link, missing `<noscript>`,
  `<pre` scroll regions without `tabindex="0"`, `aria-hidden` as the sole content of
  a `<th>`. A ~20-line Python `html.parser` check is enough — no new dependencies,
  consistent with the repo's dependency-free posture.

### S7. [P3] Findings anchor links scroll but don't move focus — persists in HEAD

- **Where:** `bin/leakage-report` (~line 603):
  `<a class="flink" href="#card-{…}">evidence →</a>` targeting
  `<section class="card …" id="card-{…}">`.
- **What:** Activating the link scrolls to the card, but the section is not focusable,
  so keyboard focus stays on the link and AT users get no programmatic indication of
  the context change.
- **Why it matters:** SC 2.4.3 (Focus Order) / 3.2 — the "evidence →" link is the
  report's main navigation aid when findings exist; it should land the user *in* the
  evidence.
- **Remediation:** add `tabindex="-1"` to the card `<section>`s and a small script
  that moves focus to the target on in-page link activation (guard it so it only runs
  for `.flink` clicks); add a `:target`/`:focus` highlight so sighted users see where
  they landed. Keep the no-JS scroll behavior as the baseline.

### S8. [P3] No-JS mode: chevron and `aria-expanded` disagree with visible content — persists in HEAD

- **Where:** `bin/leakage-report` — `<noscript><style>.detail{display:block!important}</style></noscript>`.
- **What:** With JS disabled, details render open but the chevrons still point right
  (`.card.open .chev` rotation only applies with the `open` class, which only JS adds)
  and `aria-expanded="false"` remains on the buttons.
- **Why it matters:** Minor, but it's a state lie in the exact mode (no-JS) the
  fallback was built for.
- **Remediation:** extend the noscript style with
  `.card .chev{transform:rotate(90deg)}`. The `aria-expanded` mismatch can't be fixed
  in CSS; acceptable residual — or render the noscript variant with `aria-expanded`
  omitted. Note it as known, as the project does for other residuals.

### S9. [P3] No print stylesheet — hidden evidence doesn't print — persists in HEAD

- **Where:** `bin/leakage-report` stylesheet; no `@media print` block.
- **What:** Printing (or save-to-PDF) only captures what is on screen: collapsed cards
  print as headers with no evidence, and only server-side-expanded red cards include
  their detail. An auditor printing a CLEAN report gets headers and totals but none
  of the evidence the verdict rests on.
- **Why it matters:** The report is an audit record; print/PDF is a plausible archival
  format for it. Evidence that doesn't survive printing weakens the record.
- **Remediation:** add `@media print { .detail{display:block !important} .card .chev{transform:rotate(90deg)} }`
  so the printed page is the complete record.

### S10. [P3] Small type in transcripts and labels — persists in HEAD

- **Where:** `.transcript pre{font-size:.75rem}` (12px), `.ev-label`/`.ops-label`
  `.78rem`, `.subtotal`/`.fev` `.8rem`.
- **What:** WCAG sets no minimum size, but 12px log text and 12.5px section labels are
  a readability strain, especially on phones and for low-vision users who don't run a
  screen reader.
- **Remediation:** bump transcript `<pre>` to `.8rem` and the `.78rem` labels to
  `.8rem`; the layout has room (verified: no overflow at 390px).
