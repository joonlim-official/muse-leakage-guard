## Findings

### PM-1 (P1) — CLEAN certifies an unexercised control

**What.** The user's question is "is my memory protection actually
working?" The report answers CLEAN. But the write path — the path the
daily refresh exercises every morning — contributes zero checks to that
verdict. `references/test-matrix.md` is honest about it ("not
harness-verified where CI runs"); the report is not, because the report
never distinguishes "verified" from "catalogued" for D1/D2. After the
probe set lands, the report's card C will show write-time checks alongside
the static ones, and the "Checked:" blurb must say so (currently it says
"static checks on the protection wiring" — that sentence becomes false the
moment probes are added and must be updated in the same commit).

**Recommendation.** Implement the SEC-1 probe set. In the same commit,
update `tested_blurb` for suite C ("static checks … plus write-time guard
probes over synthetic fixtures") so the report keeps its
derived-from-the-run promise.

### PM-2 (P2) — suite C's name will lie after the fix

**What.** "Attack-surface coverage (static checks)" with behavioral probes
inside is a misnomer of exactly the kind iteration 8 hunted down. Rename
to "Attack-surface coverage (controls verified in place)" — the suite's
actual job per SKILL.md ("verifies each path's stated control is actually
in place"). The report's suite-sequence assertion (`["A","B","C","D","E"]`)
forbids a new letter, so renaming in place is the honest move, not a new
suite.

### PM-3 (P3) — backlog aging, explicitly deferred

**What.** The iter-9 backlog lists SECURITY.md, issue/PR templates,
CONTRIBUTING canonical quickstart, exit-code reference, TOC, and
fixture-recipient ground rules. None is a protection gap; all are
contributor-experience items. For the final iteration, the protection-plane
work (PM-1) outranks them. Recommend carrying them as an explicit
post-loop backlog in ITERATIONS.md rather than silently dropping them.

### PM-4 (P3) — the "one improvement" scoping held, keep it

**What.** Process note: iteration 9's "one focused improvement" discipline
worked (fail-closed + send-path coverage shipped coherent). The memory-guard
probe set is similarly one theme ("write-time protection is verified, not
catalogued"). The live-fire CI assertions (SEC-3) and evasion corpus
(SEC-2) are real but separate themes — do not bundle them into iteration
10 or the commit loses its single-theme reviewability. Record them as the
post-loop backlog.
